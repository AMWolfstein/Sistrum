## Reference added by the owner (2026-10-15): MusicBeat

https://github.com/SamuelAdmand/MusicBeat at `3a7743d4ad348fbe59b01e7bcbd7054b5e130901`, GPL-3.0, a BitChord fork
(package `com.music.bitchord`). Cloned read-only to `/tmp/sistrum-refs/MusicBeat`; nothing run.

  `index.js` exporting `getLyrics(track)` / search, own registry repo (MusicBeat-Lyrics-Extensions; LRCLIB, Apple Music
  via paxsenix proxy, LyricsPlus, KuGou, Musixmatch, Genius, ...), per-provider priority, health and cache.

  first step. Gaps vs our threat model: fetch has no HTTPS/domain/private-address limits; updates download script and
  manifest from GitHub raw with no hash or signature check; Apple lyrics use a third-party proxy (rights blocker).

## Rhythm's Integrations screen (owner screenshot, 2026-10-15)

Owner asked about taking Rhythm's integrations (Deezer, LrcLib, Better Lyrics, Lyrically, Apple Music Motion Canvas,
YouTube Music, Wikipedia). Rhythm `6f26f963b82ed592ec28f05824bb7f12b65b82ea` (GPL-3.0) implements them as plain built-in
Kotlin clients (Retrofit/OkHttp), no script runtime, no native code: `app/src/main/java/chromahub/rhythm/app/infrastructure/network/`
— LRCLibApiService (76 lines, lrclib.net), BetterLyricsApiService (32, lyrics-api.boidu.dev), Lyrically via NetworkClient
(lyrics.paxsenix.org), DeezerApiService (113, api.deezer.com), WikipediaProvider (87, en.wikipedia.org REST summary),
YTMusicApiService (434, music.youtube.com internal API), AppleMusicCanvasProvider (585; scrapes the developer token from
music.apple.com's JS bundle, BuildConfig fallback token), plus DeezerArtistImageCache, CanvasNetworkMode (Wi-Fi/cellular),
LyricsApiPriorityBottomSheet. This is Phase 0's "constrained Kotlin provider adapters" option (no runtime ADR, no
downloadable code for Play). Rights/terms per service still apply (Better Lyrics/Lyrically are third-party proxies of
Apple lyrics; Apple token scraping; undocumented YTM API; Deezer terms; Wikipedia text needs CC BY-SA attribution).
