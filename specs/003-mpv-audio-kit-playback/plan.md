## Design

- **Engine.** Keep the Dart queue/playback orchestration and `MediaKitPlaybackDeck`, which already drives libmpv through the `MpvEngine` interface (equalizer `af` chain, native-playlist gapless, error mapping, AutoMix decks). Add `MpvAudioKitEngine` beside `MediaKitEngine`. mpv_audio_kit owns the `af` property, so the adapter passes the deck's chain verbatim as one `RawAudioEffect` stage (`af set`, which keeps the old chain on failure) and releases the `on_load` hook with `continueHook`. `_createDeck` returns this deck for every Android player. Skip Silence uses a `silenceremove` stage if its behavior matches the current setting; otherwise T003 records the gap for the owner.
- **Vendored package.** Copy mpv_audio_kit 0.7.2 (`b53f23d`, libmpv `r26`) into `third_party/mpv_audio_kit`, keep its BSD-3 and LGPL notices and add a Sistrum modification notice. Patches stay in that tree:
  - *Session transfer.* `MediaSessionController` binds one player through `_stateSnapshot`, `_inputs` and `_onCommand`. Add a rebind that swaps them and marks state dirty, and a `Player` method that hands the controller and `_sessionOwner` to another player without `disable`/`enable`. The native session and service stay up, so AutoMix needs no Looper-style delay.
  - *Android Auto.* Turn `MpvMediaSessionService` into a Media3 `MediaLibraryService` and build a `MediaLibrarySession` whose library callbacks (`onGetLibraryRoot`, `onGetChildren`, `onGetItem`, `onSearch`/`onGetSearchResult`, `onSetMediaItems`) ask Dart over the existing channel. `MediaLibraryService` extends `MediaSessionService`, so notification, foreground and task-removal behavior stays.
  - *Controls.* `like`/`isFavorite` and `setShuffle` exist in Dart. Add Media3 custom command buttons with Sistrum's notification drawables where Android does not render them.
- **Media session in the app.** Replace audio_service with the vendored session. Move `MediaItem`, `AudioServiceRepeatMode`, `AudioServiceShuffleMode` and `AudioProcessingState` into a local model with the same names and fields: 28 of the 45 importing files then change only their import. Port the handler logic in `music_player_service.dart`, `playback_notification.dart`, `lock_screen_lyrics.dart` (title override), `media_library_browser.dart` (browse tree reused for Android Auto) and session restore. mpv_audio_kit handles focus, interruptions and becoming-noisy, so `audio_session` is removed with it; the audio focus setting maps to `InterruptionPolicy`, and the motion-artwork video handoff (`restoreMusicAudioSessionAfterVideo`) is rechecked.
- **One decoder for analysis.** `stream.pcm` delivers overlapping display frames and is not a decode. The libmpv build includes `ao_pcm` (untimed, `ao-pcm-file`), so a headless player with no effects, volume 100 and ReplayGain off writes the decoded file as WAV faster than real time. Analysis, compare, Hi-Res check, haptics and song features read that PCM where they read FFmpeg output today. ReplayGain uses the package's EBU R128 `loudnessScan`. CUE splitting decodes with the same service and keeps Rust sample-boundary splitting and FLAC encoding (WaxFlow reference). Bit-exact output is verified against a FLAC fixture before any caller moves to it.
- **AutoMix effects.** `AutoMixEffectRenderer` pre-renders the mix tail with FFmpeg filters. Render it with the same lavfi graph through a headless libmpv player with `ao_pcm`; mpv `lavfi-complex` with an external audio file covers a two-input graph. Motion artwork validates video with FFmpeg; the audio-only libmpv has no video decoders, so validation moves to the existing `video_player` dependency.
- **Metadata and probe.** Extend the Rust tag writer to the remaining formats FFmpeg writes today, preserve unknown metadata and refuse unsupported writes before touching the file. Probe data (codec, sample rate, bit depth, channels, bitrate, duration) comes from libmpv properties of a headless player or from Rust readers.
- **Packaging.** The package build hook downloads the pinned libmpv per ABI from GitHub Releases and checks SHA-256; CI keeps that. Environments without that host pass a local, checksum-verified file through the `libmpv` user define. Remove FFmpeg kit, the C++ target with its three CMake fetches, Media3 ExoPlayer and the removed Dart/Kotlin/Rust code after every caller has a replacement. Meet LGPL duties: license page entries (registered by `MpvAudioKit.ensureInitialized`), an About line, a replaceable `libmpv.so` and source availability through the libmpv-scripts release notes. Verify 16 KB alignment of `libmpv.so` and measure the APK.

An uncommitted spike (discarded, kept outside the repository) added `MpvAudioKitEngine` and an opt-in `_createDeck` branch with mpv_audio_kit 0.7.2 from pub.dev: `flutter analyze` on the touched files reported no issues and 139 deck, completion, gapless and AutoMix tests passed. It did not run on a device: no emulator here, and GitHub Release downloads were blocked, so no libmpv binary was available. Measured arm64 sizes: FFmpeg kit 20.7 MB of native libraries, stripped `libflutter.so` 11.3 MB, libmpv 8.0–8.5 MB per the package README. Native libraries are stored uncompressed (no `useLegacyPackaging`), so the APK shrinks by roughly 12–16 MB from 62.28 MB.

## Open questions and how they are settled

- Bit-exact `ao_pcm` decode for FLAC, WAV, APE and WavPack (T006, before CUE in T009). If a format is not exact, CUE splitting refuses that source format with a clear error.
- Skip Silence equivalence through `silenceremove` (T003).
- Android rendering of favorite and shuffle as notification buttons, and Android Auto browsing on DHU (T002, T004).
- `lavfi-complex` coverage of the AutoMix tail graphs (T008).
- 16 KB alignment of the pinned `libmpv.so` and the measured APK size (T010, T011).
